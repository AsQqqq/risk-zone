# Настройка RiskZones

Полный референс по `config.yml` и `lang/`. Краткое описание - в
[README.md](../README.md)

## Кастомные зоны

Всё в `config.yml`, секция `worlds`. У каждого мира - общий центр/форма и
произвольный список зон-колец вокруг этого центра:

```yaml
worlds:
  world_nether:
    enabled: true
    center-x: 0
    center-z: 0
    shape: circle # circle (окружность) или square (чебышёвское расстояние)
    zones:
      green:
        from: 0
        to: 10000
        display-name: "Зелёная зона"
        color: "&a"
        disable-flight: false
        strip-potion-effects: []
        blocked-commands: []
        blocked-command-message: "&c..."
        reset-attributes: { ... }
        messages: { enter: { ... } }
        approach-warning: { enabled: false }
      black:
        from: 10000
        to: -1 # бесконечно
        display-name: "Чёрная зона"
        color: "&4"
        disable-flight: true
        blocked-commands: [rtp, spawn, tpa, ...]
        reset-attributes: { ... }
        messages: { enter: { ... } }
        approach-warning: { enabled: true, distance: 500, ... }
```

- Ключ секции мира (`world_nether`) - точное имя мира, как его знает Bukkit.
  Обычно у Paper это `world_nether` и `world_the_end`, но если у тебя другая
  структура миров - зайди на сервер и проверь командой `/riskzones info`,
  стоя в нужном мире
- Расстояние считается по горизонтали (X/Z), высота Y не учитывается.
  `shape`/`center-x`/`center-z` - общие на весь мир (зоны это концентрические
  кольца вокруг одного центра), а не на зону
- **`from`/`to`** - диапазон дистанции, в котором действует зона. `to: -1`
  значит "без верхней границы" (бесконечно) - но **только у зоны с
  максимальным `from` в этом мире**: при загрузке плагин проверяет, что за
  бесконечной зоной не начинается ещё одна. Если это не так (например, две
  зоны с `to: -1`, или зоны пересекаются) - конфиг некорректен, и плагин
  **отключает зоны для этого мира целиком**, с подробной причиной в логе
  при старте/`/riskzones reload`. Между зонами можно оставлять разрывы (это
  будет "вне зон" - без ограничений), а пересекаться зоны не могут
- Хочешь ещё зону - просто добавь ещё один блок под `zones:` со своим id
  (например `arena`), с любым диапазоном `from`/`to` и своими настройками
- У каждой зоны - **полностью независимый** набор из `disable-flight`,
  `strip-potion-effects`, `blocked-commands` + `blocked-command-message`,
  `reset-attributes`, `messages.enter` и `approach-warning`. Это то, что
  раньше было жёстко привязано только к чёрной зоне - теперь у любой зоны
  свои значения (см. примеры в шаблоне `config.yml` - там `green`/`black`
  показывают, как это выглядит на практике)
- `display-name`/`color` - цветное короткое имя зоны: используется в
  `/riskzones info`/`zone` и в местах, где нужно показать, в какой зоне
  игрок (это и есть настройка "цвета" зоны - сам цвет текста сообщений
  задаётся обычными `&`-кодами прямо внутри `messages.*.text`)

## Команды и права

`/riskzones reload|info|zone <игрок>` (алиасы `/rz`, `/zones`). Без
аргументов или с неизвестной подкомандой - построчная подсказка со всеми
командами; `info` и подсказка заканчиваются подвалом с указанием
разработчика и кликабельными кнопками `[Telegram]`/`[GitHub]` (ссылки -
`credits.telegram-url`/`credits.github-url` в конфиге)

| Право | Что даёт | default |
|---|---|---|
| `riskzones.admin` | доступ к команде | op |
| `riskzones.bypass.commands` | команды не блокируются ни в одной зоне | op |
| `riskzones.bypass.flight` | полёт не отключается ни в одной зоне | op |
| `riskzones.bypass.attributes` | скорость ходьбы/полёта и размер персонажа не сбрасываются ни в одной зоне | op |
| `riskzones.notify` | получать уведомления о смене зоны и приближении к зоне (чат/action-bar/title/звук) | true |

Права - глобальные (не per-зона): если игрок обошёл ограничение одним из
этих прав, оно снимается в любой зоне, где это ограничение включено. На
сервере без LuckPerms (только vanilla-опы) это самый простой вариант; если
понадобится точечно бипассить конкретную зону - это отдельная фича поверх
текущей

## Список блокируемых команд

`zones.<id>.blocked-commands` - по имени команды без `/` и без аргументов,
регистр не важен. У чёрной зоны по умолчанию уже добавлены базовые
телепорты (`rtp, spawn, tpa, tpaccept, tpahere, tpdeny, home, sethome, back,
warp, fly`) - поправь под то, что реально стоит на сервере (у Essentials/CMI/
кастомных плагинов имена и алиасы могут отличаться - впиши все алиасы,
которыми реально пользуются игроки, иначе блокировка обойдётся через алиас).
Текст сообщения об отказе - своя `blocked-command-message` у каждой зоны

## Сброс скорости/размера

`zones.<id>.reset-attributes` - при входе в зону (и постоянно, пока игрок в
ней остаётся - переналожить баф позже не выйдет) плагин сбрасывает скорость
ходьбы, скорость полёта и размер персонажа (verysmall/big и подобные
плагины донат-магазинов обычно меняют именно их) до значений, заданных тут
же. У `walk-speed`/`fly-speed`/`scale` свой `enabled`, плюс общий `enabled`
на всю секцию. `riskzones.bypass.attributes` освобождает игрока от сброса
целиком (например, для доната, у которого размер/скорость - платная
привилегия)

**`fly-speed.value` и `scale.value`** - обычные числа, которые реально
управляют игроком: `fly-speed.value` - то, что принимает `setFlySpeed`
(диапазон `-1..1`, ванильное `0.1`); `scale.value` - целевой рост
(диапазон `0.0625..16`, ванильное `1.0`)

**`walk-speed` устроен иначе - тут два независимых параметра**, потому
что на современном клиенте старое поле `setWalkSpeed` реальную скорость
ходьбы по земле уже не двигает, а влияет только на FOV (расширяется
обзор, как будто действует зелье Speed):
- `walk-speed.value` - атрибут `movement_speed`, **реальная** скорость
  (не бывает отрицательной - отрицательное значение просто обрежется до
  0, то есть заморозит игрока, а не отмотает его назад; ванильное `0.1`);
- `walk-speed.fov` - то самое косметическое поле `setWalkSpeed`, отдельно
  от `value` (диапазон `-1..1`, ванильное `0.2`) - трогай, только если
  специально хочешь несовпадающий с реальной скоростью FOV-эффект

Значения вне допустимых диапазонов обрежутся до границ, а не уронят
плагин. Независимо от `value`, дополнительно всегда снимаются модификаторы
атрибутов, добавленные **другими плагинами** (не ванильные - например,
буст от спринта не трогаем, чтобы не сбивать его собственную анимацию), и
базовое значение атрибута возвращается к нужному - на случай, если
скорость/размер выданы не через привычный API, а через `AttributeModifier`

## Предупреждение о приближении к зоне

`zones.<id>.approach-warning` - пока игрок ещё не в этой зоне, но подошёл
к её `from`-границе ближе, чем `distance` блоков, плагин шлёт
предупреждение. Срабатывает один раз при входе в эту полосу, затем
повторяется не чаще `repeat-interval-seconds` секунд, пока игрок не
отойдёт и не подойдёт снова (`0` - предупредить только один раз за
приближение). Уважает `riskzones.notify`, как и обычные уведомления.
Текст (`chat`/`action-bar`/`title`/`sound`, та же форма, что у
`messages.enter`) поддерживает плейсхолдер `%distance%` (сколько блоков
осталось, округлено вверх)

## Тексты и цвета зон - прямо в config.yml

Все тексты, которые видит игрок при смене зоны и в предупреждениях о
приближении, задаются **прямо в самой зоне** (`zones.<id>.messages.enter`,
`zones.<id>.approach-warning`) - никакого отдельного файла переводов для
этого больше нет, чтобы всё, что касается конкретной зоны, редактировалось
в одном месте. У каждого из 4 каналов (`chat`/`action-bar`/`title`/`sound`)
свой `enabled`, по умолчанию (если канал не трогать) включено всё. Цвет -
обычные `&`-коды прямо в `text`/`title`/`subtitle`

Сообщение при выходе из **любой** настроенной зоны в "не-зону" (мир без
зон, или разрыв между зонами) - одно глобальное, в `no-zone-messages`
(это не зона, а её отсутствие)

## Языки (только для команды /riskzones)

`lang/` - папка рядом с `config.yml` (`plugins/RiskZones/lang/ru.yml` и
`lang/en.yml`), создаётся сама при первом запуске и никогда не
перезаписывается автоматически. Но теперь она - **только для системных
сообщений** `/riskzones` (её ошибки, подсказки, подписи): reload/info/zone,
неизвестная подкоманда, подвал с разработчиком. Тексты самих зон - в
`config.yml`, см. раздел выше

Какой файл использовать - ключ `language` в `config.yml` (`ru`/`en`, по
умолчанию `ru`). Хочешь третий язык - скопируй `ru.yml` в `lang/<код>.yml`,
переведи и укажи этот код в `language`. `/riskzones reload` подхватывает
изменения в файлах перевода так же, как и в `config.yml`

## Интеграция с донат/ролевыми бафами

RiskZones не знает, чем именно у вас выдаются бафы (донат-плагин, LuckPerms
meta, что-то своё), поэтому это вынесено на уровень интеграции, а не зашито
жёстко:

1. **Полёт** плагин отключает сам, универсально - кэширует текущее
   `Player#getAllowFlight()` перед тем, как выключить его в зоне с
   `disable-flight: true`, и возвращает то же значение при выходе. Не
   важно, чем оно было выставлено (LuckPerms-правом, Essentials, вручную)
   - просто честно откатывается

2. **Остальные бафы** (скорость, урон и т.п., не завязанные на allow-flight)
   плагин не трогает сам - либо добавь их в `zones.<id>.strip-potion-effects`
   (если это обычные `PotionEffect`), либо твой плагин с бафами слушает наше
   событие:

   ```java
   @EventHandler
   public void onZoneChange(RiskZoneChangeEvent event) {
       ZoneDefinition to = event.getTo();     // null = игрок вне всех зон
       ZoneDefinition from = event.getFrom(); // null = был вне всех зон
       if (to != null && to.getId().equals("black")) {
           // снять свои бафы у event.getPlayer()
       } else if (from != null && from.getId().equals("black")) {
           // вернуть, если по праву/донату положено
       }
   }
   ```

   Либо дёргай статически в любой момент:
   `RiskZonesAPI.isInZone(player, "black")` / `RiskZonesAPI.getZone(player)`
   (возвращает `ZoneDefinition`, `null` - вне всех зон)

   Для этого добавь `riskzones-plugin.jar` как `provided`-зависимость в
   свой плагин (или просто скопируй `api`/`events`/`zone.ZoneDefinition`
   классы - там нет ничего специфичного)

## Известные ограничения / что не реализовано

- PvP отдельно не трогается - плагин это не меняет ни в одной из зон
- Нет защиты от абуза телепорт-предметами (эндер-жемчуг, плоды хоруса) на
  границе зон - если понадобится, легко добавить отмену
  `PlayerTeleportEvent` определённых причин рядом с границей.
- Права бипаса (`riskzones.bypass.*`) глобальные, не per-зона (см. раздел
  "Команды и права" выше) - если понадобится точечно, это отдельная фича
- Подстраховочный таймер (`safety-check-interval-ticks`, по умолчанию раз в
  5 секунд) на всякий случай пересчитывает зону всем онлайн, но не эмулирует
  фейковые Bukkit-события - дёргает внутренний сервис напрямую, чтобы не
  путать античит/другие плагины
